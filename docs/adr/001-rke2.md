# ADR 001: Use RKE2 as Kubernetes Distribution

## Status

Accepted

## Context

The Barou Platform requires a Kubernetes distribution for the homelab environment.

The platform should support:

- Kubernetes administration learning
- Infrastructure as Code
- Ansible automation
- Rancher integration
- GitOps
- security hardening
- realistic troubleshooting scenarios
- future comparison with Azure Kubernetes Service

Several Kubernetes distributions were considered, including:

- Kubernetes installed manually
- k3s
- RKE2
- Talos Linux based Kubernetes

## Decision

RKE2 will be used as the primary Kubernetes distribution.

## Reasons

RKE2 provides a good balance between operational visibility and automated deployment.

The distribution is particularly suitable for this environment because it:

- integrates naturally with Rancher
- provides a production-oriented Kubernetes distribution
- uses containerd
- supports Cilium
- allows Linux and systemd troubleshooting
- works well with Ansible automation
- provides a useful comparison point with managed Kubernetes services such as AKS

Talos Linux is intentionally not used for the primary cluster because the current learning goals include Linux administration, Ansible configuration and system-level troubleshooting.

## Consequences

The environment must manage:

- RKE2 server configuration
- RKE2 agent configuration
- cluster tokens
- Kubernetes upgrades
- operating system configuration
- networking
- firewall rules

This creates more operational responsibility than a fully managed Kubernetes service.

That additional responsibility is intentional because troubleshooting and platform operations are important learning goals.
